# Interpreter DSL

**Декларативный интерпретатор конфигураций API-эндпоинтов для Битрикс24.**

Поведение эндпоинта описывается массивом-конфигом, а не PHP-кодом в контроллере:
один движок выполняет запросы, маппинг, условия, итерации, cURL-вызовы
и сборку ответа — с единым логированием и обработкой ошибок.

> 📖 Полная документация — в папке [`docs/`](docs/) и на GitHub Pages
> (ссылка появится после первого деплоя: `https://denisv94-web.github.io/interpreter-dsl/`).

---

## Зачем это нужно

| Проблема в обычном коде                                         | Решение в интерпретаторе                               |
| --------------------------------------------------------------- | ------------------------------------------------------ |
| Каждый эндпоинт — свой контроллер со своим curl/try-catch/логом | Один движок, эндпоинт = конфиг                         |
| Логирование везде разное и пишется вручную                      | Единый формат лога: `data + params + computed + error` |
| Ошибки обрабатываются кто во что горазд                         | `on_error`, режимы `partial` / `all_or_nothing`        |
| Тесты требуют БД, сети и Битрикс                                | 130+ unit-тестов на моках, без сети и БД               |
| Новый разработчик читает 10 разных файлов                       | Читает одну документацию по DSL                        |

## Ключевые возможности

- **Выражения**: `field:a.b.c`, цепочки `field:x|field:y`, шаблоны `{{field:x}}`,
  шорткаты `{{LEAD.NAME}}`, `func:`, `method:Class->method` / `Class::method`, `result:key`
- **Условия**: равенства, `!`, `func:empty` / `func:is_numeric`, `AND`/`OR`, вложенность
- **Блок `request`**: `main`, `static` (справочники), `extra` (вычисляемые поля),
  `query` (методы классов), `curl` (внешние API)
- **`request_logic`** — произвольный порядок шагов (`['curl', 'query', 'extra']`)
- **Блок `mapping`**: одиночный режим, именованные списочные маппинги, `source` без маппинга
- **Блок `execute`**: `if / elseif / else`, `skip`, `response`-only действия,
  `change_values`, `on_error`
- **Блок `compose`**: финальная сборка ответа любой вложенности, корневое выражение
- **Итерации**: `request.array` — обработка массива объектов; ошибки итераций
  не прерывают цикл в режиме `partial`
- **`params`**: служебные параметры запуска, доступны везде как `field:params.x`
- **Логирование**: флаг `logging` на действие, `error_response` — свои поля в ERROR-записи

## Требования

| Окружение                 | Что нужно                                                                         |
| ------------------------- | --------------------------------------------------------------------------------- |
| **Автономно (ПК, CI)**    | PHP **8.1+** (CLI). Больше ничего: тесты идут без Битрикс, Git и БД               |
| **Продакшен (Битрикс24)** | Битрикс24, корпоративные `Logger` / `ResponseHandler` подставляются автозагрузкой |

Проверено на: PHP 8.3, Битрикс24 26.150.0.
