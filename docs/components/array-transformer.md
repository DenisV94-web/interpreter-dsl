# ArrayTransformer — трансформация списков объектов

`ArrayTransformer` — отдельный сервис для преобразования списков
объектов: перегруппировка, переименование полей, применение
PHP-функций и методов классов к отдельным полям.

Отдельный сервис рядом с `ArrayFilter` — не смешиваем «фильтрацию»
и «перегруппировку» (SRP).

---

## toSelectOptions — список опций с трансформацией

Превращает список объектов в список опций для select/select2.
Каждое поле выхода описывается **декларативно** — новые трансформации
добавляются без правок сервиса (OCP).

### Формы правил

```php
'primary_results' => [
    'method' => 'toSelectOptions',
    'class'  => \Api\Services\ArrayTransformer::class,
    'params' => [
        'field:pr_hl',
        [
            // 1. Прямая копия поля
            'value'  => 'UF_CODE',
            'label'  => 'UF_REFLECTED_VALUE',

            // 2. PHP-функция
            'showIf' => ['fn' => 'json_decode', 'args' => ['item:UF_SHOW_IF', true]],
            'code'   => ['fn' => 'strtoupper', 'args' => ['item:UF_CODE']],

            // 3. Метод класса (статический)
            'custom' => ['fn' => [\App\Utils::class, 'fmt'], 'args' => ['item:NAME']],

            // 4. Цепочка трансформаций (рекурсия)
            'full'   => [
                'fn' => 'trim',
                'args' => [['fn' => 'strtoupper', 'args' => ['item:NAME']]],
            ],

            // 5. Item-шаблон: склейка полей текущей строки (v1.19.1)
            'fio'    => '{{item:LAST_NAME}} {{item:NAME}} {{item:SECOND_NAME}}',
        ],
    ],
],
```

### Доступ к полям текущей строки

`item:ИМЯ_ПОЛЯ` — значение поля из текущей строки итерации.
Это внутренний префикс `ArrayTransformer` (не DSL): он **не резолвится**
Field Resolver'ом и доходит до сервиса как литерал, а сервис уже
подставляет `$item['ИМЯ_ПОЛЯ']` на каждой итерации.

> ⚠️ Не путать с `result:X` — это DSL-префикс «поле из результата
> последнего вызова метода», который резолвится **один раз до**
> передачи в сервис и для итерационных трансформаций не подходит.

## Item-шаблоны `{{item:X}}` (v1.19.1)

Строковое правило маппинга с плейсхолдерами `{{item:PATH}}`
резолвится по **текущей строке** списка — удобно для склейки
полей (ФИО, подпись с подразделением):

```php
'users' => [
    'method' => 'toSelectOptions',
    'class'  => \Api\Services\ArrayTransformer::class,
    'params' => [
        'field:USERS_BY_DEP',
        [
            'id_user' => 'ID',
            'fio'     => '{{item:LAST_NAME}} {{item:NAME}} {{item:SECOND_NAME}}',
            'label'   => '{{item:NAME}} ({{item:DEPT.TITLE}})',
        ],
    ],
],
```

Семантика:

- точечная нотация: `{{item:DEPT.TITLE}}` — вложенные массивы;
- null → `''` (Twig-семантика), boolean → `'1'`/`'0'`;
- массив/объект в плейсхолдере → `''`, список не падает;
- итоговая строка trim'ится — хвостовые пробелы от null-полей
  убираются: `'Иванов Иван '` → `'Иванов Иван'`;
- строка **без** плейсхолдеров `{{item:` ведёт себя как раньше —
  прямая копия поля по имени.

### Отличие от `fn`+`args`

| Задача                                                | Чем делать                         |
| ----------------------------------------------------- | ---------------------------------- |
| склейка полей и литералов в строку                    | item-шаблон                        |
| функция/метод над полем (`strtoupper`, `json_decode`) | `fn`+`args`                        |
| цепочка трансформаций                                 | `fn`+`args` с вложенными массивами |

### Правила маппинга

| Форма                                          | Что делает                                                     |
| ---------------------------------------------- | -------------------------------------------------------------- |
| `'ИМЯ_ПОЛЯ'` (строка)                          | прямая копия поля как есть                                     |
| `['fn' => 'func', 'args' => [...]]`            | вызов PHP-функции с аргументами                                |
| `['fn' => [Class, 'method'], 'args' => [...]]` | статический метод                                              |
| `['fn' => 'Class::method', 'args' => [...]]`   | статический метод (сахар)                                      |
| массив `['fn' => ...]` внутри `args`           | вложенная трансформация (цепочка)                              |
| строка с `{{item:PATH}}`                       | шаблон: плейсхолдеры подставляются из текущей строки (v1.19.1) |

### Обработка ошибок

- отсутствующее поле в источнике → `null` в результате;
- исключение из `fn`/метода → `null` в поле (весь список не падает);
- невалидный JSON в `json_decode` → `null`;
- не найденный путь в item-шаблоне → `''` в этом плейсхолдере (вся строка не падает).

### Результат

```json
[
  {
    "value": "NO_ANSWER",
    "label": "Нет ответа",
    "showIf": { "field": "contact_occurred", "operator": "eq", "value": "0" }
  }
]
```

## renameKeys — переименование ключей

```php
'renamed' => [
    'method' => 'renameKeys',
    'class'  => \Api\Services\ArrayTransformer::class,
    'params' => [
        'field:items',
        ['ID' => 'id', 'NAME' => 'name'],
    ],
],
```

Ключи, не указанные в алиасах, сохраняются как есть.

## toMap — список в карту (v1.20.0)

Декларативный аналог JS `list.forEach(v => { map[v[key]] = v[value]; })`:

```php
'primary_result_codes' => [
    'method' => 'toMap',
    'class'  => \Api\Services\ArrayTransformer::class,
    'params' => [
        'field:primary_results',   // исходный список
        'value',                   // поле-ключ
        'label',                   // поле-значение
    ],
],
```

Результат: `{'A': 'Alpha', 'B': 'Beta'}` — готовая карта для выдачи
фронту (без сборки в JS) и для точечных луков в конфиге:
`field:primary_result_codes[field:code]`.

- строка без поля-ключа → пропускается;
- дубли ключа → побеждает последний;
- нет поля-значения → `null` под этим ключом.

## applySchema — схема отображения строки (v1.21.0)

Декларативная замена фронтовых маппингов вида `key → {title, variant}`:
схема задаёт состав, порядок, заголовки, словари подмены и форматы
дат; выход готов к рендеру.

```php
'attempts_view' => [
    'method' => 'applySchema',
    'class'  => \Api\Services\ArrayTransformer::class,
    'params' => [
        'field:attempts',                 // строка или список строк
        [                                 // схема: порядок = порядок вывода
            'primary_result_code' => [
                'title'   => 'Основной код результата CRM',
                'variant' => 'field:primary_result_codes',   // словарь code → label
            ],
            'successful_contact'  => [
                'title'   => 'Контакт состоялся',
                'variant' => [1 => 'Да', 0 => 'Нет'],         // встроенный словарь
            ],
            'appointment_at'      => [
                'title'  => 'Запланированная встреча',
                'format' => 'd.m.Y H:i:s',                    // формат даты
            ],
            'contact_attempt_id'  => ['title' => 'ИД результата', 'fade_in' => false],
            'comment'             => ['title' => 'Комментарий менеджера'],
        ],
        ['blank' => [null, '', '0000-00-00 00:00:00']],       // что считать пустотой
    ],
],
```

Выход — ассоциатив с ключами **полей данных** (порядок = порядок схемы):

```json
{
  "primary_result_code": {
    "title": "Основной код результата CRM",
    "value": "Занято"
  },
  "successful_contact": { "title": "Контакт состоялся", "value": "Нет" },
  "appointment_at": {
    "title": "Запланированная встреча",
    "value": "31.08.2026 09:49:00"
  },
  "contact_attempt_id": {
    "title": "ИД результата",
    "fade_in": false,
    "value": "c07794ff-…"
  },
  "comment": { "title": "Комментарий менеджера", "value": "недозвон" }
}
```

Для списка строк на входе — список таких объектов (по одному на строку).

Порядок применения правила: `blank` → `variant` → `format` → сырое значение.

Правила:

- `variant` — словарь подмены; нет сырого значения в словаре →
  сырое значение (новые коды не теряются);
- `variant` => `field:...` резолвится на этапе резолва параметров —
  словари из `toMap`/`static` подключаются без кода;
- `format` — формат даты: значение проходит через `strtotime()` +
  `date()`; непарсируемая дата → дата от timestamp 0, поэтому
  мусорные значения (`0000-00-00 00:00:00`) держите в `blank`;
- значения из списка `blank` → `''` (дефолт `[null, '']`);
- отсутствующее поле → `''`;
- правило-строка (`'comment' => 'Комментарий'`) — сахар: только title,
  значение как есть;
- лишние ключи правила (`fade_in` и свои) проходят в выход как есть —
  подсказки для фронта без отдельных соглашений.

Фронт: `Object.entries(attempt).forEach(([key, pair]) => …)` —
схема и словари в JS больше не живут.

## query в applySchema — батчинг запросов (v1.22.0)

Правило схемы может подтягивать значение из внешнего сервиса:
уникальные значения поля собираются по всем строкам, выполняется
**один** запрос с `IN`, строится lookup-таблица.

```php
'detail_view' => [
    'method' => 'applySchema',
    'class'  => \Api\Services\ArrayTransformer::class,
    'params' => [
        'field:contact_result',
        [
            'dealer_center_id' => [
                'title' => 'Подразделение',
                'query' => [
                    'method' => 'getDepartments',
                    'class'  => \Api\User\Main::class,
                    'params' => [
                        ['ID' => '@batch'],   // список уникальных ID
                        ['ID', 'NAME'],       // select: ID для связывания, NAME для значения
                    ],
                    'key_field'   => 'ID',    // поле связывания (ключ кэша)
                    'value_field' => 'NAME',  // поле-значение
                    'on_error'    => 'raw',   // 'raw' | 'null'
                ],
            ],
            'manager_id' => [
                'title' => 'Менеджер',
                'query' => [
                    'method' => 'getList',
                    'class'  => \Api\User\Main::class,
                    'params' => [
                        [   // обёртка: один positional-аргумент — массив параметров
                            'filter' => ['ID' => '@batch'],
                            'select' => ['ID', 'NAME'],
                        ],
                    ],
                    'key_field'   => 'ID',
                    'value_field' => 'NAME',
                ],
            ],
        ],
        ['blank' => [null, '', '0000-00-00 00:00:00']],
    ],
],
```

Семантика:

- `@batch` — маркер в `params`, заменяется списком уникальных
  значений поля (рекурсивно, на любой глубине вложенности params);
- `params` — список positional-аргументов метода: если метод
  принимает один массив (`getList`) — оберните filter/select
  в дополнительный массив, иначе аргументы «разъедутся»;
- пустой batch (все null) → query пропускается;
- `key_field` + `value_field` → lookup-таблица `cache[raw] = value`;
- `value_field` — массив: берётся первый элемент;
- `on_error`: `'raw'` (дефолт) — сырое значение + WARNING, `'null'` —
  null + ERROR; применяется и к упавшему query, и к значению,
  не найденному в кэше;
- `Method` и `Context` передаются в `applySchema` автоматически
  при вызове из extra/query/execute (инъекция в `Method::execute()`
  после резолва params); при прямом вызове сервиса без них query
  не выполняются, значение остаётся сырым.

Производительность: N строк × M query-полей = **M запросов**
(по одному на поле), а не N×M.

## applyInstructions — инструкции изменения полей (v1.14.0)

Применяет инструкции из декодированного JSON-маппинга
(например, `UF_JSON_MAPPING_FIELDS` HL-блока) к текущим значениям:

```php
'lead_update' => [
    'method' => 'applyInstructions',
    'class'  => \Api\Services\ArrayTransformer::class,
    'params' => [
        'field:decoded_mapping',   // json_decode(UF_JSON_MAPPING_FIELDS, true)
        'field:params.lead',       // текущие значения лида
        'field:mapping_values',    // значения для инструкций field:*
    ],
],
```

| Инструкция         | Пример                                   | Результат                  |
| ------------------ | ---------------------------------------- | -------------------------- |
| инкремент          | `"UF_CALL_COUNT": "UF_CALL_COUNT++"`     | `(int) current + 1`        |
| значение контекста | `"UF_CALL_DATE": "field:next_action_at"` | `values['next_action_at']` |
| литерал            | `"UF_DO_NOT_CONTACT": "1"`               | `'1'`                      |

- инструкции — это **данные**, а не DSL-выражения: конфликтов с `field:` нет;
- `null`-инструкции (пустой JSON) → пустой массив;
- дальше payload дособирается через `array_merge` (например, с условными
  полями подразделения из `dep_fields`) и уходит в `execute` на update.

## projectTree — проекция (select) полей дерева (v1.24.0)

Оставляет в дереве только нужные поля: срезает payload перед выдачей
фронту и уменьшает `log.computed`.

```php
'deps_view' => [
    'method' => 'projectTree',
    'class'  => \Api\Services\ArrayTransformer::class,
    'params' => [
        'field:deps_filtered',
        [
            ''           => ['department', 'users'],          // поля строки корня
            'department' => ['ID', 'NAME', 'UF_TELEPHONY', 'editPlan'],
            'users'      => ['ID', 'LAST_NAME', 'NAME', 'PERSONAL_PAGER' => ''],
        ],
    ],
],
```

Формы select:

| Форма     | Пример                       | Нет поля в строке     |
| --------- | ---------------------------- | --------------------- |
| список    | `['ID', 'NAME']`             | `null`                |
| маппинг   | `['NAME' => 'Аноним']`       | указанный дефолт      |
| смешанная | `['ID', 'NAME' => 'Аноним']` | по форме каждого поля |

Правила:

- порядок полей выхода = порядок select;
- дефолт подставляется только при **отсутствии ключа**; ключ со
  значением `null` остаётся `null`;
- путь `''` — проекция строк корневой коллекции;
- путь в assoc-массив → проецируется как строка; путь в список →
  проецируется каждая строка (ключи списка сохраняются);
- путь в скаляр или отсутствующий путь — не трогается;
- уровни применяются по возрастанию глубины: вложенный путь
  (`users.tags`) должен пережить select родительского (`users`);
- дефолты резолвятся как выражения: `'F' => 'field:params.fallback'`,
  `{{ }}`; литерал с префиксом-выражением — через `literal:`.

Связка с filterTree (v1.23.0): сначала фильтрация строк, затем
проекция полей — двумя вызовами в extra/query/execute.

## fillEmpty — замена пустых значений (v1.25.0)

Сохраняет строки целиком (без проекции) и подменяет значения
указанных полей, если они пусты. Кейс: селект не нужен, но «дыры»
в данных нужно заткнуть для отображения.

```php
'deps_filled' => [
    'method' => 'fillEmpty',
    'class'  => \Api\Services\ArrayTransformer::class,
    'params' => [
        'field:departments_map',
        [
            'users'      => ['PERSONAL_PAGER' => '—'],
            'department' => ['UF_PHONE_CITY' => 'не указан'],
        ],
        ['empty_values' => [null, '', '0000-00-00 00:00:00']],  // опционально
    ],
],
```

Правила:

- триггеры пустоты: дефолт `[null, '']`; опция `empty_values`
  переопределяет набор целиком (не дополняет);
- замена только если ключ присутствует и значение пусто;
  отсутствующий ключ НЕ создаётся;
- сравнение строгое: `0`, `'0'`, `false` пустыми не считаются;
- семантика путей как в `projectTree`: `''` — строки корня,
  `'users'` — список/объект, точечные пути; скалярный или
  отсутствующий путь игнорируется;
- замены резолвятся как выражения: `'F' => 'field:params.fallback'`,
  `{{ }}`; литерал с префиксом-выражением — через `literal:`.

Типовая цепочка: `filterTree` (строки) → `projectTree` (поля) →
`fillEmpty` (дыры); либо `fillEmpty` по полным данным без проекции.

## collect — сборка нового массива из дерева (v1.26.0)

Извлекает значения из многомерной коллекции в **новый** массив —
одномерный или многомерный (группировки, карты). В отличие от
`projectTree`/`fillEmpty` форму источника не сохраняет.

```php
// плоский список всех внутренних номеров (пустые пропускаются)
'pagers' => [
    'method' => 'collect',
    'class'  => \Api\Services\ArrayTransformer::class,
    'params' => [
        'field:departments_map',
        ['from' => 'users', 'value' => 'PERSONAL_PAGER'],
    ],
],

// карта подразделение → номера
'pagers_by_dep' => [
    'params' => [
        'field:departments_map',
        ['from' => 'users', 'value' => 'PERSONAL_PAGER', 'group_by' => '_key'],
    ],
],

// многомерность: телефония → подразделение → карта user → номер
'pagers_tree' => [
    'params' => [
        'field:departments_map',
        [
            'from'     => 'users',
            'value'    => 'PERSONAL_PAGER',
            'group_by' => ['department.UF_TELEPHONY', '_key'],
            'key_by'   => 'ID',
        ],
    ],
],
```

Спека:

| Ключ         | Дефолт | Смысл                                                                                                           |
| ------------ | ------ | --------------------------------------------------------------------------------------------------------------- |
| `from`       | `''`   | путь до итерируемой коллекции внутри строки корня; `''` — сами строки корня                                     |
| `value`      | —      | точечный путь по строке, `_key`, `@self` (сам элемент), `{{item:X}}`-шаблон, вложенная спека collect (рекурсия) |
| `group_by`   | null   | путь(и) по строке-владельцу; `_key` — ключ владельца; массив путей = вложенные группы                           |
| `key_by`     | null   | поле итерируемой строки: внутренний уровень становится картой                                                   |
| `skip_empty` | true   | не собирать значения из набора пустот                                                                           |
| `unique`     | false  | дедупликация значений (строгое сравнение) внутри каждой итоговой коллекции                                      |

Опции третьим аргументом: `['empty_values' => [null, '']]` —
переопределить набор пустот целиком (как в `fillEmpty`).

Правила:

- пустые группы не создаются: группа появляется, только когда в неё
  легло хотя бы одно значение;
- ключ группы или `key_by` = null/отсутствует/массив → значение
  пропускается;
- порядок групп — по первому появлению, значений — по порядку обхода;
- скоуп: `value`/`key_by` — по итерируемой строке, `group_by` — по
  строке-владельцу (корневой строке при `from != ''`);
- вложенная спека `value` использует текущую строку как источник;
- числовые ключи нормализуются PHP в int (как везде в DSL).

## patchTree — условный патчинг строк дерева (v1.27.0)

Находит строки по условию (грамматика Condition) и добавляет
или перезаписывает поля. Кейс: «если PERSONAL_PAGER пуст —
выставить PERSONAL_PAGER_ERROR».

```php
'users_patched' => [
    'method' => 'patchTree',
    'class'  => \Api\Services\ArrayTransformer::class,
    'params' => [
        'field:departments_map',
        [
            [
                'from'  => 'users',                          // '' = строки корня
                'where' => ['PERSONAL_PAGER' => 'func:empty'],
                'set'   => ['PERSONAL_PAGER_ERROR' => 'Нет внутреннего номера'],
            ],
            [
                'from'  => '',
                'where' => ['department.UF_TELEPHONY' => '2566'],
                'set'   => ['TELEPHONY_GROUP' => 'TMN'],
            ],
        ],
    ],
],
```

Правило:

| Ключ    | Смысл                                                                                                                             |
| ------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `from`  | точечный путь до итерируемой коллекции (`''` — корень)                                                                            |
| `where` | Condition-грамматика по строке: `logic` AND/OR, вложенные группы, операторы Битрикс, `_key`, `func:`-проверки; пусто → все строки |
| `set`   | поле => значение: ключа нет → добавляется, есть → перезаписывается                                                                |

Значения `set`:

- литералы и выражения об глобальный контекст (`field:`, `date:`,
  `{{ }}`) — резолвятся до вызова через resolveParams;
- `{{item:X}}` — шаблон по полям текущей строки;
- `item:X` — сырая копия значения поля строки с типом.

Правила применяются последовательно: следующее видит изменения
предыдущего (каскады). Скалярные/отсутствующие пути не трогаются.

### func:-проверки в where (общие для filterTree и patchTree)

Whitelist оценатора `TreeConditionMatcher` (v1.27.0):

| Проверка          | Эквивалент                           |
| ----------------- | ------------------------------------ |
| `func:empty`      | `empty($v)`                          |
| `func:blank`      | `$v === null \|\| $v === ''`         |
| `func:is_null`    | `$v === null` (нет поля → тоже true) |
| `func:is_numeric` | `is_numeric($v)`                     |
| `func:is_array`   | `is_array($v)`                       |
| `func:is_string`  | `is_string($v)`                      |

Отрицание — префиксом `!`/`!=` в ключе: `'!X' => 'func:empty'`.
Неизвестный `func:` → условие false. Отсутствующее поле: для
`func:` = null (семантика Condition), для литеральных условий —
строка исключается (как в filterTree 1.23.0).

**Важно (v1.27.2):** правая часть `'func:empty'` в боевых конфигах
приходит в метод дескриптором `['type' => 'function', 'name' => 'empty']`
(resolveParams гоняет params через Field до вызова метода).
`TreeConditionMatcher` понимает обе формы: строку и дескриптор.
`literal:func:empty` передаёт строку как есть (без превращения в дескриптор).

## enrichFromLookup — джоин строк с внешней картой (v1.28.0)

Прикрепляет к строкам коллекции объекты из внешней карты (lookup)
по значению поля-ключа. Кейс: статусы SIP-extensions телефонии
к сотрудникам по `PERSONAL_PAGER`.

```php
'users_with_sip' => [
    'method' => 'enrichFromLookup',
    'class'  => \Api\Services\ArrayTransformer::class,
    'params' => [
        'field:users_view',        // дерево с коллекциями
        'field:sip.extensions',    // карта: ключ => объект
        'users',                   // путь до коллекции ('' — строки корня)
        'PERSONAL_PAGER',          // поле строки для поиска
        'SIP_STATUS',              // имя нового поля
    ],
],
```

Правила:

- поле-ключ пусто (`null`/`''`) или отсутствует → строка не трогается;
- ключ найден в lookup → весь объект lookup пишется в целевое поле;
- ключ не найден → `null` в целевом поле: фронт отличает «нет ключа»
  от «ключ не найден в телефонии»;
- ключи сравниваются как строки: числовые ключи `json_decode`
  (int `3500`) и строковые значения полей (`'3500'`) матчатся;
- путь до коллекции — точечный (`a.users`); скалярные/отсутствующие
  пути не трогаются.
