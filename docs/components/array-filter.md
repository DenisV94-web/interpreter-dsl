# ArrayFilter — фильтрация массивов по фильтру в стиле Битрикс

`ArrayFilter` — отдельный сервис для фильтрации списков объектов
по нескольким условиям с операторами фильтра Битрикс.
Вызывается из любого места DSL, где поддерживаются `method` + `class`
(extra, query, execute, static), а также напрямую из PHP-кода.

---

## Вызов из конфига

```php
'filtered_items' => [
    'method' => 'filter',
    'class'  => \Api\Services\ArrayFilter::class,
    'params' => [
        'field:items',          // исходный список
        [                       // фильтр в стиле Битрикс
            '!UF_CHECK_DEPARTMENT' => 1,
            'UF_REASON_REFUSAL'    => 0,
            '>COUNT'               => 10,
        ],
    ],
],
```

Результат пишется в контекст и доступен как `field:filtered_items`.

---

## Операторы

| Оператор   | Пример                         | Значение                            |
| ---------- | ------------------------------ | ----------------------------------- |
| нет / `=`  | `'STATUS' => 'NEW'`            | равно (сравнение слабое, `==`)      |
| `!` / `!=` | `'!STATUS' => 'JUNK'`          | не равно                            |
| `>`        | `'>COUNT' => 10`               | больше                              |
| `<`        | `'<COUNT' => 100`              | меньше                              |
| `>=`       | `'>=COUNT' => 10`              | больше или равно                    |
| `<=`       | `'<=COUNT' => 100`             | меньше или равно                    |
| `%`        | `'%TAG' => 'import'`           | LIKE: подстрока, регистронезависимо |
| `@`        | `'@STATUS' => ['NEW', 'PROC']` | IN: значение в списке               |
| `!@`       | `'!@STATUS' => ['JUNK']`       | NOT IN                              |

---

## Семантика

- условия объединяются через **AND**: строка попадает в результат,
  только если выполнены все условия;
- поле отсутствует в строке → строка не попадает в результат;
- сравнение слабое (`==`, `in_array(..., false)`): строка `"0"`
  равна числу `0` — как в фильтрах Битрикс;
- исходный массив не изменяется — возвращается новый;
- пустой фильтр возвращает исходный список как есть.

---

## Типовые кейсы

### Поиск по нескольким параметрам

```php
'matched' => [
    'method' => 'filter',
    'class'  => \Api\Services\ArrayFilter::class,
    'params' => [
        'field:primary_results',
        ['!UF_CHECK_DEPARTMENT' => 1, 'UF_REASON_REFUSAL' => 0],
    ],
],
```

### Словарь из списка — не сюда

`ArrayFilter` не собирает словари. Для пары «ключ из одного поля,
значение из другого» используйте `array_column`:

```php
'dict' => [
    'method' => 'array_column',
    'params' => ['field:items', 'UF_REFLECTED_VALUE', 'UF_CODE'],
],
```

## filterTree — фильтрация многомерных коллекций (v1.23.0)

Фильтрует дерево данных уровнями: каждый уровень — путь до коллекции

- условия + политика ключей. Кейс: карта «подразделение → пользователи»,
  где надо отобрать подразделения по полям и почистить пользователей внутри.

```php
'deps_filtered' => [
    'method' => 'filterTree',
    'class'  => \Api\Services\ArrayFilter::class,
    'params' => [
        'field:departments_map',
        [
            '' => [                                   // корень
                'filter' => [
                    'logic' => 'OR',
                    'department.UF_TELEPHONY' => '2566',
                    'department.UF_INTEGRATION_1C' => '11823',
                ],
                'keep_keys' => true,                  // сохранить ключи карты
            ],
            'users' => [                              // уровень внутри каждого элемента
                'filter' => ['@UF_DEPARTMENT' => [451, 790]],
                'keep_keys' => false,                 // reindex в список
                'drop_empty' => true,                 // пустых владельцев убрать
            ],
        ],
    ],
],
```

Спека уровня:

| Опция        | Дефолт              | Смысл                                                                                                                                        |
| ------------ | ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `filter`     | `[]` (всё проходит) | условия грамматикой Condition: `logic` AND/OR, вложенные группы, Bitrix-операторы в ключах (`@`, `!@`, `<=`, `>=`, `%`, `!=`, `!`, `<`, `>`) |
| `keep_keys`  | `false`             | `true` — сохранить ключи отфильтрованной коллекции, `false` — reindex                                                                        |
| `drop_empty` | `false`             | `true` — владелец коллекции, ставшей пустой после фильтра, удаляется (каскада между уровнями нет)                                            |

Правила:

- путь `''` — корневая коллекция; `'users'`, `'users.tags'` — точечные
  пути от элемента корня; уровни применяются по возрастанию глубины;
- скоуп условий — элемент фильтруемой коллекции; точечная нотация
  (`department.UF_TELEPHONY`) спускается по вложенным массивам;
- `_key` — псевдополе: ключ элемента в его коллекции
  (`'@_key' => [451, 790]` — отбор подразделений по ключам карты);
- `@`/`!@` по полю-массиву: достаточно пересечения одного значения
  (как IN по мульти-полю в Битрикс); сравнения нестрогие;
- нет поля у элемента → условие false → строка исключается
  (семантика плоского `filter`);
- правая часть условий резолвится до вызова (`resolveParams`):
  `'field:params.region'` справа = значение из контекста;
- числовые ключи карты нормализуются PHP в int (и в конфиге, и при
  json_decode); в JSON-ответе они снова сериализуются строками —
  для фронта разницы нет;
- `where`-условия filterTree с v1.27.0 понимают `func:`-проверки
  whitelist (`empty`, `blank`, `is_null`, `is_numeric`, `is_array`,
  `is_string`) через общий оценатор `TreeConditionMatcher`;
  литеральные условия поведения не меняют.
