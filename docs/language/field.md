# Выражения (Field Resolver)

**Выражение** — всё, что стоит в позиции «значение» в конфиге:
в `extra`, `mapping`, `params`, `response`, `compose`.
Field Resolver превращает выражение в конкретное значение.

---

## Литералы и типы

Всё, что не распознано как специальная конструкция, возвращается как есть:

| Вход                 | Результат                             |
| -------------------- | ------------------------------------- |
| `'NEW'`              | строка `'NEW'`                        |
| `42`, `true`, `null` | то же значение того же типа           |
| `['a' => 1]`         | массив как есть                       |
| `'unknown:value'`    | строка как есть (неизвестный префикс) |

---

## `field:` — чтение из контекста

```php
'field:name'            // контекст['name']
'field:CONTACT.NAME'    // контекст['CONTACT']['NAME'] — точечная нотация
'field:A.B.C.D'         // любая глубина
```

Правила:

- поле не найдено → `null` (без исключения);
- ключи с точкой в имени не поддерживаются (точка = разделитель пути);
- работает во всех блоках и внутри шаблонов `{{ }}`.

---

## Цепочка альтернатив `|`

```php
'field:CONTACT_PHONE.VALUE|field:COMPANY_PHONE.VALUE|field:phone'
```

- возвращается **первое найденное** (не `null`) значение;
- все `null` → результат `null`;
- работает внутри `{{ }}`: `{{field:A|field:B}}`.

Типичный кейс — телефон контакта, иначе компании, иначе из запроса.

---

## Шаблоны `{{ }}`

Строка, содержащая `{{ выражение }}`, становится шаблоном:

```php
'Клиент {{field:NAME}}, тел: +{{field:phone}}'
// → 'Клиент Иван, тел: +79990000000'
```

### Семантика

| Случай                                  | Результат                                            |
| --------------------------------------- | ---------------------------------------------------- |
| Текст + плейсхолдеры                    | Строка с подстановкой                                |
| `null` в плейсхолдере внутри текста     | Пустая строка: `'+{{field:phone}}'` → `'+'`          |
| Одиночный `{{выражение}}` на всю строку | **Сырое значение с типом** (число останется числом)  |
| `+` снаружи скобок                      | Обычный литерал: `'+{{field:phone}}'` → `'+7999...'` |

### Шорткаты (голые пути)

Внутри `{{ }}` префикс `field:` можно не писать:

```php
'{{LEAD.LAST_NAME}} {{LEAD.NAME}} {{LEAD.SECOND_NAME}}'
// → 'Иванов Иван '   (null-отчество дало пустую строку)
```

Голый путь — идентификатор с точками: `LEAD.NAME`, `user_id`.

### Скобки-литералы

Если внутри `{{ }}` **нет** похожего на путь выражения — скобки остаются:

```php
'a {{ 100 }} c'   // → 'a {{ 100 }} c'  (100 — не путь)
'a {{ b }} c'     // → 'a  c'           (b — валидный шорткат, null → '')
```

## `func:` — функции для условий

```php
'func:empty'        // проверка «пусто»
'func:is_numeric'   // проверка «число»
```

В позиции значения возвращает служебную структуру
`['type' => 'function', ...]` — предназначена для **условий**
(см. [Условия](conditions.md)), а не для подстановки значений.

---

## `method:` — ссылка на метод класса

```php
'method:App\Service->isUnactive'   // instance-метод (static: false)
'method:App\Service::isUnactive'   // статический (static: true)
```

- возвращает дескриптор `{class, method, static}` — используется
  в условиях `execute` и `filter`;
- статичность определяется по разделителю (`->` / `::`);
- формат без класса (`method:someMethod`) → структура с `error`
  («Invalid method format»), а не исключение.

> Не путать с вызовом метода: вызов делается в `extra`/`query`
> через блок `['method' => ..., 'class' => ...]` (см. Method Resolver).

---

## `result` — результат последнего действия

```php
'result'        // весь результат последнего вызова метода
'result:ID'     // поле результата
```

`lastResult` обновляется после каждого вызова в `extra`/`query`/`execute`.

## Сводная таблица

| Конструкция           | Пример               | Результат                      |
| --------------------- | -------------------- | ------------------------------ |
| Литерал               | `'NEW'`              | `'NEW'`                        |
| Поле                  | `'field:A.B'`        | значение или `null`            |
| Цепочка               | `'field:A\|field:B'` | первое не-null                 |
| Шаблон                | `'{{A}} {{B}}'`      | строка, null → `''`            |
| Одиночный плейсхолдер | `'{{count}}'`        | сырое значение (5, а не `'5'`) |
| Шорткат               | `'{{LEAD.NAME}}'`    | как `{{field:LEAD.NAME}}`      |
| Функция               | `'func:empty'`       | структура для условий          |
| Метод                 | `'method:C->m'`      | дескриптор для условий         |
| Результат             | `'result:ID'`        | поле последнего результата     |

## Где какие конструкции работают

| Позиция в конфиге                                     | Допустимые конструкции                                                          |
| ----------------------------------------------------- | ------------------------------------------------------------------------------- |
| Значения `extra` / `mapping` / `compose` / `response` | литералы, `field:`, цепочки, `{{ }}`, `result:`                                 |
| `params` методов                                      | всё вышеперечисленное + `'mapping'` + вложенные массивы (резолвятся рекурсивно) |
| `filter` / `conditions`                               | равенства, `!field:`, `func:*`, `method:*` — см. [Условия](conditions.md)       |

## Динамический ключ: field:имя[ключ] (v1.7.0)

Значение одного поля можно взять, используя другое поле как ключ:

```php
'field:pr_hl[field:index_code]',   // ключ приходит из поля index_code
```

Работает везде, где резолвятся выражения: extra, query, mapping,
execute, compose, curl, conditions и шаблоны `{{ }}`.

### Что допустимо внутри `[...]`

| Форма              | Пример                 | Значение                                                           |
| ------------------ | ---------------------- | ------------------------------------------------------------------ |
| `field:`           | `field:arr[field:key]` | ключ из поля (рекурсивно, включая цепочки `\|` и вложенные скобки) |
| литерал в кавычках | `field:arr['NEW_CAR']` | строковый ключ                                                     |
| число              | `field:list[1]`        | числовой индекс                                                    |
| голое имя          | `field:arr[code]`      | литеральный ключ `code`                                            |

### Комбинации с точечной нотацией

```php
'field:a.b[field:k].name',     // точка до и после скобок
'field:m[field:r][field:c]',   // несколько скобок подряд (матрицы)
```

### Семантика

- отсутствующий ключ или null-ключ → `null` (без исключения, как весь DSL);
- разделитель `|` учитывает глубину скобок: цепочка
  `field:a[field:x|field:y]|field:b` не ломается на внутренней `|`;
- непарная скобка → читаемая ошибка парсинга.

### В шаблонах

Работают обе формы:

```php
'{{field:pr_hl[field:index_code]}}',   // полная форма
'Статус: {{pr_hl[field:index_code]}}', // шорткат
```

## Рекурсивный резолв значений (v1.17.0)

Значения в контексте сами могут быть выражениями. Если `field:x`
разрешился в строку с префиксом `field:` / `date:` / `literal:` —
она разрешается дальше, до конечного значения:

```php
// контекст: ref1 = 'field:ref2', ref2 = 'field:final', final = 42
'field:ref1'   // → 42
```

Массивы обходятся рекурсивно — строки-выражения разрешаются
на любой глубине:

```php
// контекст: config = ['name' => 'field:product_name', 'n' => ['id' => 'field:product_id']]
'field:config' // → ['name' => 'iPhone', 'n' => ['id' => 123]]
```

Защита: лимит глубины 10 и контроль циклов
(`field:a → field:b → field:a` → null + ERROR в лог).
Рекурсивно разрешаются только `field:` / `date:` / `literal:` —
строки `func:` / `method:` / `result` в данных остаются как есть.

## Date-выражения (v1.17.0)

Вычисление дат через strtotime(). Работает **и напрямую в конфиге,
и через данные** (HL-блоки):

```php
'date:"+1 day"'                        // now + 1 день, формат d.m.Y H:i:s
'date:"-2 hours; d.m.Y H:i"'          // now − 2 часа, свой формат
'date:"+4 minutes"'                   // now + 4 минуты
'date:"@field:appointment_at +1 day"' // база из поля + модификатор
'date:"@field:test_drive_at; d.m.Y"'  // база из поля, только дата
'date:"tomorrow; d.m.Y"'              // любые strtotime-модификаторы
```

Грамматика: `date:"<модификатор>[; <формат>]"`; база задаётся как
`@<выражение> <модификатор>` (по умолчанию база = now).
Формат по умолчанию `d.m.Y H:i:s`. Ошибка парсинга → null + ERROR в лог.

Кейс: поле HL `UF_DEADLINE_ACTIVITY` хранит `field:appointment_at`
или `date:"+1 day"`; в конфиге пишется
`'field:params.settings.UF_DEADLINE_ACTIVITY'` — движок сам
до-разрешает значение до конечной даты.

## Literal escape (v1.17.0)

Если данные начинаются с `field:` / `date:`, но должны остаться
текстом — префикс `literal:`:

```php
'literal:field:test'    // → строка "field:test" как есть
'literal:date:"+1 day"' // → строка 'date:"+1 day"' как есть
```

## Формулы: постфиксная арифметика (v1.18.0)

Фаза 1: постфикс-операторы на `field:`/`result:`-выражениях.
Вычисляет новое значение без побочных эффектов:

```php
'field:lead.UF_CALL_COUNT++'      // значение + 1
'field:num--'                     // значение − 1
'field:num+2' / 'field:num + 2'   // значение + 2
'field:price-0.5'                 // значение − 0.5
```

Постфикс применяется к результату всего операнда —
цепочки и скобки поддерживаются:

```php
'field:a|field:b++'       // (a или b) + 1
'field:arr[field:key]++'  // значение по динамическому ключу + 1
```

Семантика:

- операнд null → null (WARNING в лог);
- нечисловой операнд → null (WARNING);
- числовые строки ("4") приводятся к числу;
- целый результат → int, дробный → float.

Текст, который не должен вычисляться, экранируется
`literal:`: `literal:field:x++` → строка "field:x++".
