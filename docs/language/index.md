# Обзор языка DSL

Конфиг интерпретатора — это обычный PHP-массив. Один элемент верхнего
уровня = один **эндпоинт** (действие). Движок читает массив и выполняет
описанное — без PHP-кода в контроллере.

---

## Скелет конфига

```php
'имя_действия' => [
    // Служебные ключи
    'logging'        => true,        // false — не писать в логгер
    'error_response' => [            // свои поля в ERROR-записи итерации
        'task_id' => 'field:task_id',
    ],

    // Блоки данных и логики
    'request' => [
        'main'          => 'post',   // источник входных данных
        'array'         => 'items',  // ОПЦИОНАЛЬНО: итерационный режим
        'request_logic' => ['extra', 'curl', 'query'],  // ОПЦИОНАЛЬНО: свой порядок
        'static'  => [ /* справочники */ ],
        'extra'   => [ /* вычисляемые поля */ ],
        'query'   => [ /* вызовы методов классов */ ],
        'curl'    => [ /* HTTP-запросы */ ],
    ],

    'mapping' => [ /* сборка полей сущности / списков */ ],
    'execute' => [ /* бизнес-логика: if/elseif/else, действия */ ],
    'compose' => [ /* финальная сборка ответа */ ],

    // Транзакции (для итерационного режима)
    'transaction' => ['enabled' => true, 'mode' => 'partial'],

    // Порядок выполнения блоков
    'action_logic' => ['request', 'mapping', 'execute', 'compose'],
],
```

Все блоки, кроме `request`, **опциональны**. `action_logic` перечисляет
только те, что реально используются.

---

## Два режима выполнения

| Режим        | Условие                   | Поведение                                                              |
| ------------ | ------------------------- | ---------------------------------------------------------------------- |
| Одиночный    | нет ключа `request.array` | Данные обрабатываются один раз                                         |
| Итерационный | `request.array = 'ключ'`  | Цикл по массиву; каждая итерация проходит все шаги; ошибки изолируются |

В итерационном режиме:

- данные вне массива — общие для всех итераций;
- `transaction.mode = 'partial'` — ошибка итерации пишет запись
  `ERROR` в ответ и цикл продолжается;
- `transaction.mode = 'all_or_nothing'` — первая ошибка останавливает всё;
- снимки вычисленных данных каждой итерации попадают в лог
  (`computed.iteration_N`).

## Порядок выполнения

```text
Interpreter::run()
 ├─ валидация конфига (ConfigException с путём)
 ├─ входные данные + params
 └─ для каждого шага action_logic:
     ├─ request
     │   ├─ main (данные в контекст)
     │   └─ шаги в порядке request_logic
     │       (по умолчанию: static → extra → query → curl)
     ├─ mapping
     ├─ execute
     └─ compose
```

Внутри `request` каждый следующий шаг видит результаты предыдущих —
это позволяет строить цепочки: `curl → расшифровать → query по результату`.

Ошибка в любом шаге останавливает последующие (кроме режима `partial`
на уровне итераций — там останавливается только текущая итерация).

## Глоссарий

| Термин                | Значение                                                                                                          |
| --------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **Контекст**          | Хранилище данных текущего запуска: входные поля, вычисленные поля, `params`, результаты запросов                  |
| **Выражение**         | Строка, разрешаемая в значение: `field:x`, `{{x}}`, `func:empty`, литерал                                         |
| **Resolver**          | Компонент, разрешающий выражения: `Field`, `Condition`, `Method`                                                  |
| **Executor**          | Компонент, выполняющий блок: `Request`, `Mapping`, `Execute`, `Curl`, `Compose`                                   |
| **params**            | Служебные параметры запуска (4-й аргумент `run()`); доступны как `field:params.x` и `{{params.x}}` во всех блоках |
| **rawRequest**        | Сырые входные данные — попадают в лог как `data`                                                                  |
| **computed**          | Вычисленные поля (всё, что не rawRequest и не params) — попадают в лог                                            |
| **Снимок (snapshot)** | Копия computed на момент конца итерации — для лога                                                                |
| **on_error**          | Fallback при ошибке запроса/метода: значение или `{status, data}`                                                 |
| **conditions**        | Условие выполнения запроса/действия; ложное → `SKIPPED`                                                           |

---

## Как читать чужой конфиг: алгоритм

1. `action_logic` — какие блоки и в каком порядке работают.
2. `request.array` — одиночный или итерационный режим.
3. `request` — откуда приходят данные и что вычисляется.
4. `mapping` — какие поля собираются и из чего.
5. `execute` — ветвления и действия (создание/обновление/skip).
6. `compose` — что вернётся клиенту.
