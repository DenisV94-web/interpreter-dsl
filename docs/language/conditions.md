# Условия (Condition Resolver)

Условие — массив пар «ключ => проверка». Результат — `true`/`false`.
Условия управляют выполнением запросов, действий и ветвлений.

---

## Где применяются и что делает `false`

| Позиция в конфиге               | При `false`                                                |
| ------------------------------- | ---------------------------------------------------------- |
| `query[x].conditions`           | запрос не выполняется, поле = `null` (`SKIPPED` в логе)    |
| `curl[x].conditions`            | запрос не выполняется, результат = `null` (`SKIPPED`)      |
| `extra[x].conditions`           | берётся ветка `check_false` вместо `check_true`            |
| `execute[i].filter`             | блок пропускается, проверяется следующий (`elseif`/`else`) |
| `execute actions[j].conditions` | действие пропускается (цикл продолжается)                  |

---

## Формат проверки

Ключ — выражение поля (с `!` или без), значение — способ проверки:

```php
'conditions' => [
    'field:client_type' => 'contact',        // равенство
    '!field:LEAD.ID'    => 'func:empty',     // функция с отрицанием
    'field:phone'       => 'func:is_numeric',
]
```

По умолчанию все проверки в массиве объединены **AND**.

---

## Равенство (нестрогое, `==`)

```php
'field:client_type' => 'contact'   // value == 'contact'
'field:clean_phone' => false       // value == false
```

Особенности PHP-сравнения, которые работают на тебя:

| Значение поля | `== false` | Смысл           |
| ------------- | ---------- | --------------- |
| `false`       | `true`     | явный false     |
| `null`        | `true`     | поля нет        |
| `''`          | `true`     | пустая строка   |
| `'0'`         | `true`     | ноль-строка     |
| `'+7999...'`  | `false`    | непустая строка |

Поэтому «нет или невалидно» проверяется одной парой:
`'field:VALID_PHONE' => false`.

---

## Отрицание `!`

`!` инвертирует значение поля **до** проверки:

```php
'!field:LEAD.ID' => 'func:empty'   // «LEAD.ID не пуст» (лид найден)
```

| Поле          | `!field` | `func:empty` от инверсии | Смысл                      |
| ------------- | -------- | ------------------------ | -------------------------- |
| `null` / `''` | `true`   | `false`                  | пусто → условие ложно      |
| `555`         | `false`  | `true`                   | не пусто → условие истинно |

---

## `func:`-проверки

| Проверка            | Истинна, когда             |
| ------------------- | -------------------------- |
| `'func:empty'`      | значение пусто (`empty()`) |
| `'func:is_numeric'` | значение числовое          |

---

## `method:`-проверки

```php
'field:dealer_center_id' => 'method:DesktopManager\User->isUnactive'
```

Метод вызывается со значением поля в качестве аргумента;
результат интерпретируется как булев. Разделители `->` / `::`
работают как в [выражениях](field.md#method-ссылка-на-метод-класса).

> В `execute` чаще используется блочная форма — `method`/`class`/`params`
> на уровне блока (см. [execute](../executors/execute.md)):
> там параметры метода задаются явно, а не берутся из поля.

---

## Логика `AND` / `OR`

```php
'filter' => [
    'logic' => 'OR',                       // по умолчанию — AND
    'field:unified_client_id' => 'func:empty',
    'field:segment_code'      => 'func:empty',
],
```

- `AND` (умолчание): истинны **все** проверки;
- `OR`: достаточно **одной**.

---

## Вложенные условия

Значением проверки может быть другой массив условий —
он вычисляется рекурсивно и участвует как один операнд:

```php
'conditions' => [
    'field:client_type' => 'contact',
    'field:CONTACT' => [                    // вложенный блок
        'logic' => 'OR',
        '!field:CONTACT.PHONE' => 'func:empty',
        'field:CONTACT.EMAIL'  => 'func:empty',
    ],
],
```

---

## Сводка форм

| Ключ       | Значение       | Смысл                     |
| ---------- | -------------- | ------------------------- |
| `field:x`  | литерал        | `x == литерал`            |
| `!field:x` | литерал        | `(инверсия x) == литерал` |
| `field:x`  | `func:name`    | `name(x)`                 |
| `!field:x` | `func:name`    | `name(инверсия x)`        |
| `field:x`  | `method:C->m`  | `m(x)` как булев          |
| `field:x`  | массив         | вложенные условия         |
| `logic`    | `'AND'`/`'OR'` | объединение проверок      |

---

## Динамические условия из данных (v1.15.0)

`conditions` может быть не только статическим массивом в конфиге,
но и строкой — ссылкой на массив в контексте:

```php
'query' => [
    'decoded_conditions' => [
        'method' => 'json_decode',
        'params' => ['field:result_row.UF_CONDITIONS', true],
    ],
],

'extra' => [
    'lead_update' => [
        'conditions' => 'field:decoded_conditions',
        'check_true' => [ /* применяем */ ],
        'check_false' => [],
    ],
],
```

Семантика «условие выполнения» из HL-блока:

| Данные                     | Результат    |
| -------------------------- | ------------ |
| поле пустое                | выполнять    |
| заполнено, условие истинно | выполнять    |
| заполнено, условие ложно   | не выполнять |

Синтаксис пар внутри JSON — стандартный для условий
(`{"<=field:max_calls_allowed": "field:contact_result_count"}`).
